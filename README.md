## 高峰期模式（重要）

抢课开放的那几分钟，服务器会被几千人同时打：响应从 1 秒变十几秒、
大量 502/504、会话被踢、名额几秒就没了。**晚上人少时跑得通，不等于高峰期能用。**

界面上默认勾着「**高速直投提交接口**」，它和普通方式的区别是：

| | 读页面 | 提交 | 30 秒能投几次 |
|---|---|---|---|
| 浏览器点击 | 每次都要 | 点按钮 + 等弹窗 | 个位数 |
| **高速直投** | **只读一次** | 直接 POST 提交接口 | **几十次** |

原理：先读一次选课页把目标课的 `jxb_id` 拿到手，之后**不再读页面**，
直接对着提交接口高频投。正方的提交接口本身很轻（一个 POST 就完事），
而选课列表页服务器要生成一两秒 —— 高峰期的胜负就在这几秒。

**高峰期正确用法：提前 5~10 分钟打开、登录、填好课、点开始。**
开放前显示「待命、提交 0 次」是正常的，它在等正确时机。
中途掉线会用账号密码自动重登（正方不需要验证码）。

## 重要修复（本次）

### 1. 提交地址前缀重复 —— 所有选课提交都打在 404 上

`base_url` 是 `http://jwxt.cumtxh.cn/jwglxt`（已含 `/jwglxt`），
但 `submit_select` / `diagnose_select_endpoints` / `_select_referer`
又拼了一次 `/jwglxt`，实际请求变成：

```
http://jwxt.cumtxh.cn/jwglxt/jwglxt/xsxk/xsxk_operate.html
```

结果：**12 种候选端点组合全部落到"页面不存在"，`submit_select` 只会抛
"没能找到可用的选课端点"**。这就是"真实提交从未验证"的根因。

代码里其实有一行注释提醒过（`SELECT_PAGE_PATHS` 那处已修），但提交路径漏了。
现已修复，并在 `test_sim.py url` 与 `test_peak.py` 里加了回归测试。

### 2. `kch_id` 解析不出来

`parse_courses` 只会从 `kch_id=xxx` 这种形式提取，而正方真实页面用的是
`xsxk('jxb_id','X','kch_id','Y')` 这种 JS 调用形式 —— 结果课程代码一直是空。
现已兼容。

### 3. 故障种类没有分清

原来 `FATAL_MARKS` 把三件完全不同的事混在一起：

- `"不在选课时间内"` → 还没开放，**应该继续投**
- `"登录超时"` → 会话掉了，**应该自动重登**
- `"无选课权限"` → 真的没戏，才该停

混在一起会导致：没开放时直接停掉（正好错过开闸瞬间），或者会话掉了
却不重登。现在 `zf_peak.classify_submit` 把它们分成
`ok / already / full / not_open / session / gateway / stop / unknown`，
不同种类走不同处理。

### 4. 高峰期探测一遇抖动就白扫一圈

`find_select_page` 每次都从候选列表第一个开始试，一次网络抖动就要
重扫全部候选。压测里这一条让 brutal 档的定位耗时到了 60 秒级。
现在 `find_page` 优先复用**已经确认过的地址**（快路径），
brutal 档定位时间降到 2~4 秒。

## 高峰期压测（`test_sim.py`）

`sim_server.py` 会起一个本地"教务站"，可以注入：慢响应、随机 5xx、
连接被掐断、请求卡死、会话过期、名额被抢、**响应丢失**（服务器其实
选上了但回程丢包）。

它**自己生成一对 RSA 密钥，用私钥真的解密**客户端传来的密文再比对明文 ——
所以客户端的裸 RSA（无 PKCS#1 填充、定长大端输出）只要有一点不对就会被识破，
而不是两边共用同一个错误实现。

最近一次全量运行结果（7 个场景，全部 0 失败）：

| 场景 | 结果 |
|---|---|
| **三档强度** normal | 定位 0.2 秒，0.3 秒抢到 |
| **三档强度** peak（25% 请求失败） | 定位 1.1 秒，开放瞬间抢到（提交 8 次，7 次被回"未开放"） |
| **三档强度** brutal（51% 请求失败） | 定位 2.0 秒，扛住 15 次 502 + 4 次断连后抢到 |
| 地址拼接 | 6 个地址全部无重复前缀 |
| 会话中途过期 | 自动重登 1 次，56 秒后抢到 |
| 响应丢失 | 0.8 秒靠「已经选过」回执确认成功 |
| 全站 5xx | 没崩，恢复后 0.9 秒抢到 |
| 密码错误 | 明确提示「用户名或密码不正确」，密文本身合法 |
| 未开放 | 知道开放时间→待命 0 次提交；不知道→8 秒投 23 次，节奏不退让 |

**关于胜率的实话**：peak / brutal 两档里服务器分别有 25% / 51% 的请求在
失败，对手又在开放后 2~4 秒就来抢 —— 比现实恶劣得多，单次存在小概率
抢不到。所以测试对这两档允许重试，normal 档是确定性必须成功。

#### 账密登录是怎么实现的（重要技术说明）

本校教务系统有两个坑，导致"自己算加密"这条路走不通：

1. **RSA 公钥是动态的** —— 每取一次 `login_getPublicKey.html` 就签发一个新密钥
2. **自行实现的加密结果会被服务端判为密码错误** —— 即使算法与前端逐位一致、
   即使使用刚刚取到的新密钥，服务端仍然拒绝；而浏览器用同样的密码就能通过

因此**账密登录不是自己算加密**，而是让浏览器来完成"填表 + 加密 + 提交"这一步
（即最贴近真实用户行为的做法），成功后把会话 cookie 转成 HTTP 会话。
这样既**可靠**（登录走浏览器，一定能过），又**快**（读课程走 HTTP）。

> 也正因如此，账密登录时会短暂启动一个**无头浏览器**（不显示窗口），属正常现象。

### 抢课是怎么做到"开放瞬间就抢到"的

选课开放前**看不到任何课程**——课程只在你点"选课"的那一刻才出现，而且全校同时挤进去。
程序为此做了几层设计：

| 机制 | 解决什么问题 |
| --- | --- |
| **HTTP 优先读取** | 实测 0.3 秒一次；浏览器渲染要几秒 |
| **接口自适应发现** | 选课页的表格接口地址是**开放时才注入**的。程序在页面出现表格后，**直接问页面自己**（读 jqGrid 实例配置）拿到真实地址，不靠猜 |
| **自动触发查询** | 有些学校要先选「学年/学期」或点「查询」才出课程，程序会自动做这一步 |
| **自动刷新页面** | ⚠️ **关键**：如果选课页是开放**前**打开的，它不会自己长出表格。程序每 25 轮自动重新加载页面 |
| **双通道取数据** | JSON 接口 + 浏览器 DOM，谁有数据用谁 |
| **区分两种"没有课"** | 页面可读但无课 → **保持你设的间隔**持续监测；读取失败才退避 |
| **浏览器点击提交** | 点学校自己的「选课」按钮，不依赖任何猜测的接口 |
| **原生弹窗正确应答** | confirm/alert 用 CDP 抓文字后点「确定」—— 保证走到"同意"分支 |
| **实时刷新课表** | 一旦读到课程，立刻填充到界面表格里，你能看到有哪些课 |
| **eager 加载** | DOM 就绪即返回，不等图片，慢服务器上快很多 |
| **浏览器必关** | 无论成功失败都强制关闭，不留僵尸进程 |

> 这几条里最关键的两条是「**区分两种没有课**」和「**自动刷新页面**」：
> 少了任何一条，程序都会在选课开放的那一刻**毫无反应**。

## 一、登录机制（已对真实服务器验证）

这个版本的教务系统密码是 **RSA 加密**后提交的，不是老版本正方用的 DES。脚本完整复刻了前端的加密链路：

| 步骤 | 请求 | 说明 |
| --- | --- | --- |
| 1 | `GET /jwglxt/xtgl/login_slogin.html` | 建立会话 Cookie，从页面取出 `csrftoken` |
| 2 | `GET /jwglxt/xtgl/login_getPublicKey.html` | 拿到 RSA `modulus` / `exponent`（base64） |
| 3 | 本地计算 | `cipher = pow(密码的整数形式, e, n)`，再 base64 |
| 4 | `POST /jwglxt/xtgl/login_slogin.html` | 表单 `yhm` / `mm`(密文) / `csrftoken` / `language` |
| 5 | 判定 | 成功会跳转；失败页面回显 `用户名或密码不正确` |

> 关键细节：正方前端 `rsa.js` 的 `RSAKey.encrypt` **不做 PKCS#1 填充**，服务端按"裸 RSA"解密。
> 所以脚本必须用裸 `pow(m, e, n)`，**不能**加 PKCS#1 填充，否则服务端解不出来。

实测确认：`modulus` 为 1024 位，密文固定 128 字节（base64 后 172 字符）。

## 二、快速开始

### 0. 准备（Windows / macOS / Linux 都一样）

```bash
python grab.py --help
```

如果 `python` 不存在，也可以用 `uv`：

```bash
uv run python grab.py --help
```

### 1. 先跑诊断模式（**强烈建议第一次先做这步**）

```bash
python grab.py --user 你的学号 --password 你的密码 --discover
```

它会：
- 登录并显示是否成功
- 拉取主菜单，列出所有"选课"相关入口
- 探测选课页面，把 HTML 存到 `discover/` 目录
- 尝试解析出课程列表和 `jxb_id`

**为什么必须先做这一步？** 选课页面只有在"选课开放期间"才会返回真正的课程列表；不在开放期时，教学班里没有任何数据，脚本也就拿不到 `jxb_id`。诊断模式能明确告诉你现在处于哪种情况。

### 2. 查看可选课程，拿 `jxb_id`

```bash
python grab.py --config config.json --list
```

输出形如：

```
jxb_id               详情
------------------------------------------------------------
3F0A1B2C...          高等数学A | 张老师 | 周一3-4节 | 60/60 | 选课
4D5E6F70...          大学英语   | 李老师 | 周二1-2节 | 45/50 | 选课
```

### 3. 开始抢课

```bash
python grab.py --config config.json --course 4D5E6F70 --interval 0.3
```

多个目标用逗号分隔：`--course 4D5E6F70,3F0A1B2C`

### 4. 定时开抢（例如选课 08:00 开放）

```bash
python grab.py --config config.json --course 4D5E6F70 --at "08:00:00"
```

## 三、浏览器模式（推荐，不接触密码）

如果密码登录一直失败，或者你平时是**微信扫码 / 统一身份认证**登录的，用这个模式：

```bash
pip install selenium
python grab.py --browser --login-only
```

流程是：

1. 脚本弹出 Edge 浏览器窗口，打开登录页
2. **你自己在里面登录**（手输密码或扫码，脚本完全不接触你的密码）
3. 脚本检测到登录成功后，**接管浏览器会话**（把 Cookie 搬到 HTTP 客户端）
4. 后续抢课全部走高效的 HTTP 请求，不再需要浏览器

常用组合：

```bash
# ★ 最推荐：一次跑完自检，产出完整排查报告
python grab.py --browser --selfcheck

# 只验证会话有效
python grab.py --browser --login-only

python grab.py --browser --list

python grab.py --browser
```

### `--selfcheck` 自检模式

一次跑完四步，把排查需要的全部信息打出来：

1. **会话状态** —— 登录是否有效
2. **主菜单里的选课入口** —— 找出真实的模块路径
3. **选课页面探测** —— 命中路径、学期选项、解析到的课程与 `jxb_id`
4. **选课端点诊断** —— 用**假 `jxb_id`** 逐个打候选端点，看服务端真实响应

第 4 步是重点：它**不会真的选中任何课**（用的假 ID），但能判断出哪个端点/传参方式是"活的"——
返回业务错误（如"教学班不存在"）说明端点有效，返回 404 / 空响应 / 登录页说明端点不对。

适合用在：脚本还没适配你学校、或者抢课时提示"没能找到可用的选课端点"。

### 顺便抓取真实登录请求（排查用）

```bash
python grab.py --browser --login-only --dump-login login_request.json
```

这会把**浏览器真实发出的登录请求**（URL + Payload）保存下来。如果密码登录失败，
用它和脚本发出的请求一对比就能看出差异在哪。

> 如果自动找不到浏览器，加 `--browser-binary "C:\path\to\msedge.exe"`。

## 六、脚本怎么判断"抢到了"

正方返回的结果五花八门，脚本按下面的优先级归类：

| 归类 | 触发条件 | 处理方式 |
| --- | --- | --- |
| **成功** | JSON `flag=1`，或含 `选课成功` | 移出目标，打印成功横幅 |
| **已是你的课** | 含 `已选过` / `重复选课` / `已选定` | 视为成功，跳过（课程本来就在课表里） |
| **没抢到，重试** | 含 `已满` / `容量已满` / `余量不足` 等 | 继续轮询 |
| **放弃该课** | 含 `不在选课时间内` / `无选课权限` / `未开放` | 停止抢这门课，继续抢其它 |
| **掉线** | 响应又是登录页 | 自动重新登录后继续 |
| **端点不对** | 404 / 500 / 返回 HTML | 换下一个候选端点 |

端点与传参方式是**自动探测**的：脚本会依次尝试
`xsxk_operate` / `xsxk_xk` / `xsxk_xkBc` / `xsxk_saveXk` / `xsxk_doXk` 等路径，
以及 `POST 表单`、`GET 查询串` 两种方式，**第一个被服务端接受的组合会被记住**，
之后轮询只走这一条路径，保证速度。

## 七、如果 `--discover` 说"没能定位选课页面"

4. 找到那个请求，把它的 **URL** 和 **表单参数** 记下来
5. 用 `--modules` 和 `--gnmkdm` 传进去，例如：
   ```bash

   ```

## 九、注意事项

- **请只用于自己的账号。** 不要拿去帮别人抢、不要拿去刷课、不要做任何转卖或代抢。
- **别把 `--interval` 调到 0。** 会给学校服务器造成压力，也容易触发风控 / 封 IP。
  默认 `0.35` 秒 + 抖动已经足够快。
- 脚本**不做验证码绕过**。如果学校开启了登录验证码（当前未开启），需要人工介入。
- 学校教务系统升级后，页面结构 / 端点可能变化，脚本需要相应调整。
- `config.json` 里含明文密码，**不要提交到 Git，不要外发**。
