程序在你自己的电脑上运行，账号密码只发往学校服务器，
不经过任何第三方。它不存密码，只（可选）记住你的账号。


----------------------------------------------------------------
一、第一次使用（只做一次）
----------------------------------------------------------------

1. 装 Python 3
   打开 python.org 下载 Windows 版安装包。
   安装时**务必勾选**这两项：
     [x] Add Python to PATH
     [x] tcl/tk and IDLE
   不勾的话程序起不来。

2. 把整个 jwxt_course_grabber 文件夹放在桌面（或者任何地方都行）。

3. 双击【启动抢课助手.bat】。


----------------------------------------------------------------
二、每次抢课怎么操作
----------------------------------------------------------------

1. 选择登录方式（默认「账号密码」这一项就够了）。
   填学号和密码，点【登 录】。
   正方教务**没有验证码**，所以登录比南审那套省事。

2. 等它读到选课页。下面的表格会列出可选课程。

3. 填"想抢什么课"：
   最省事的办法是**在表格里双击那门课**，课程名会自动填进去。
   也可以手填课程代码 / 课程名称 / 教师名，几个条件都填就是"且"关系。

4. 确认「高峰期模式」是勾上的（默认就勾着），提交间隔保持 0.5 秒。

5. 点【▶ 开始抢课】。

6. 抢到会写在下面对话框里，并自动停止。


----------------------------------------------------------------
三、高峰期正确姿势（最重要的一节）
----------------------------------------------------------------

高峰期指选课刚开放的那几分钟：几千人同时挤，服务器响应从 1 秒
变成十几秒，大量 502/504，会话会被踢，名额几秒就没了。

正确做法：

  ● **提前 5~10 分钟**打开脚本、登录、填好课，然后点开始。
    程序会先把目标课定位好，然后在开放前几秒开始连续提交。
    开放那一刻它已经在投了。

  ● 开放前看到"阶段：抢课 / 提交 0 次"是**正常的**。
    它在等正确时机，不是在偷懒。**不要因为看着没动静就反复点开始。**

  ● 抢课过程中**别关窗口**。中途掉线它会自己用账号密码重登
    （正方不需要验证码，所以能全自动续上）。

  ● "提交间隔"保持默认 0.5 秒。调太小是给服务器添乱，
    也容易被风控盯上。

  ● 课程名写得越**具体**，匹配越准、定位越快。


----------------------------------------------------------------
四、两种抢课方式有什么区别
----------------------------------------------------------------

【高速直投（推荐，默认勾选）】
  只用 HTTP。先读一次页面把目标课的内部编号拿到手，
  之后**不再读页面**，直接对着"提交选课"接口高频投。
  快就快在这里：读页面要一两秒，提交只要几十毫秒。
  高峰期的胜负就在这几秒。

【浏览器点击（不勾选时）】
  用 Edge 打开学校页面、点页面上的"选课"按钮，读弹窗提示。
  走的是学校自己的前端逻辑，最"原汁原味"，
  但每次都要驱动浏览器：点按钮、等弹窗、解析页面，慢很多。

平时用哪种都行；**高峰期建议用高速直投**。

五、界面上的字都是什么意思
----------------------------------------------------------------

  学号 / 密码        统一身份认证（学号 + 教务密码）
  显示密码           把密码框变成明文，方便检查
  课程代码/名称/教师  抢课目标，填了的条件是"且"关系
  课程类型           不限 / 必修 / 选修…
  轮询间隔(秒)       多久回读一次课程页面
  高峰期模式         勾上 = 高速直投提交接口
  提交间隔(秒)       发出选课请求的间隔，默认 0.5

  ▶ 开始抢课   ■ 停止   打开选课页   刷新课程
  查看我的课表           查已选课程
  导出表格               调试用，把页面存下来

  状态栏（一行）：
     阶段        扫描 → 抢课 → 已抢到 / 已停止
     提交 N 次   已经向服务器发起的选课请求数
     网关重投    因为 502/504 自动重投的次数
     结果不明    请求超时但对端可能已处理的次数
     自动重登    掉线后自动重新登录的次数

  下面的对话框：每一步动作的详细日志。

六、常见问题
----------------------------------------------------------------

【一直"待命"、"提交 0 次"，是不是卡住了？】
  不是。页面写了选课开放时间时，程序会等到开放前几秒才开投，
  免得白刷几个小时。日志里会写"还有 N 秒"。

【一直回"不在选课时间内"刷了很久】
  说明还没到开放时间。让它继续跑就行，不用管它。

【日志里出现"网关报错，立刻重投"】
  正常，高峰期服务器就是这样。网关错误说明请求根本没到应用，
  程序会立刻重投，不用管。

【日志里出现"提交结果不明"】
  说明请求超时或连接被掐断了 —— 服务器**可能已经把你选上了**。
  程序会再投一次：如果服务器回"已经选过该课程"，那就是成功了。
  这种情况不会漏判成功，也不会重复选两门。

【提示"该教学班人数已满"】
  这门课名额没了。换别的课或别的教师。

【提示需要重新登录 / 自动重登失败】
  会话被服务器踢了。正方不需要验证码，程序会自动重登；
  只有在密码改了或账号被锁时才需要你手动处理。

【密码填错了会怎样？】
  会明确提示"用户名或密码不正确"。注意连续错太多次账号会被锁定，
  请谨慎重试。

【抢成功了，但我还想确认一下】
  点【查看我的课表】。

【关掉窗口后还在后台跑吗？】
  不会，关窗口就停了。

【配置文件在哪？】
  gui_last.json（以及 config.example.json 作参考）。
  里面只存账号和几个参数，可以随时删；删掉不影响使用。


----------------------------------------------------------------
七、如果程序起不来
----------------------------------------------------------------

【双击 bat 一闪而过】
  说明 Python 没装好。重新装 Python，记得勾
  "Add Python to PATH" 和 "tcl/tk and IDLE"。

【提示 tkinter is missing】
  重新运行 Python 安装包 → 选 Modify → 勾上
  "tcl/tk and IDLE" → 装完再试。

【想看看到底哪里出错】
  在文件夹里按住 Shift 右键 → "在此处打开 PowerShell/终端"，
  然后输入：
      python gui.py
  错误信息会显示在窗口里，不会一闪而过。
